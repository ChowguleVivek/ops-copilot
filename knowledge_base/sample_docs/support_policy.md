# Support Ticket Handling Policy

## Priority Levels
- **High**: Production outage, data loss risk, or security issue. Must be
  turned into a follow-up task and assigned within 1 business hour.
- **Medium**: Feature not working as expected but a workaround exists.
  Follow-up task should be created within 1 business day.
- **Low**: Cosmetic issues, feature requests, documentation gaps. Batch
  these into a weekly review rather than individual tasks.

## Auto-escalation Rules
Any ticket mentioning "down", "outage", "can't log in", or "data missing"
should always be treated as High priority regardless of how the customer
phrased it.

## Task Creation Rules
Every ticket that is not resolved in the first response must have a
corresponding task created on the team board, tagged with the originating
ticket ID so it can be traced back.

## Weekly Reporting
Every Friday, a summary report should be generated covering: number of
tickets received, number resolved, number of open follow-up tasks by
priority, and any tickets that breached their SLA.
